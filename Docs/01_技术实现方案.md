# 《昆吾禁地》Godot 技术实现方案

版本：Godot-1.0  
引擎基线：Godot `4.7.1` + GDScript + GL Compatibility  
当前平台：macOS/桌面编辑与运行；后续可导出移动端和 Web

> 本文是当前工程的技术事实源。迁移前引擎方案只保留在
> [`LegacyCocos/01_技术实现方案.md`](LegacyCocos/01_技术实现方案.md) 中作审计。

## 1. 技术目标

- 使用独立 Godot 工程完成启动、营地、入山整备、地图探索、战斗与归营闭环。
- 产品规则由 `Docs/1.0策划案/` 和 `Docs/PRD/` 约束，运行路径、场景和节点以当前 Godot
  实现为准。
- 不依赖 Node.js、浏览器存储、旧引擎编辑器或上级工程。
- 保持 `375×817` 逻辑视口、nearest filtering 和整数像素边界。

## 2. 工程基线

| 项目 | Godot 实现 |
|---|---|
| 启动入口 | `res://scenes/boot.tscn` |
| 全局状态 | `Game` autoload，脚本为 `res://scripts/autoload/game.gd` |
| 营地 | `res://scenes/camp.tscn` + `res://scripts/scenes/camp.gd` |
| 地图 | `res://scenes/map.tscn` + `map_scene.gd` + `map_canvas.gd` |
| 战斗 | `res://scenes/combat.tscn` + `combat.gd` + `domain/combat_resolver.gd` |
| 数据 | `res://data/**/*.json` |
| 存档 | `user://kunwu_profile.json` |
| UI 工厂 | `res://scripts/ui/ui.gd` |
| 地形工具 | Map01：高清背景 + JSON 语义网格；TileMapDual `v5.0.2` 仅作未来地图可选工具 |

`project.godot` 固定使用 GL Compatibility、Canvas Items 拉伸和 nearest texture filter。

## 3. 分层与数据流

```text
JSON 配置 / 存档
        ↓
Game autoload（状态、事务、场景路由）
        ↓
领域结算器（纯规则）
        ↓
场景脚本（用例编排）
        ↓
Control / Node2D / CanvasItem（表现与输入）
```

规则层不得依赖按钮、标签或动画节点。战斗始终按
`CombatCommand → 结算器 → CombatEvent → 表现层` 流动。

## 4. 数据与资源

- 运行 JSON 只从 `res://data/` 读取，由 `Game._load_json()` 集中解析。
- 运行图片、字体和地图资源位于 `res://assets/`。
- `art/source_archive/`、`third_party/` 与 `Docs/Artifacts/` 是编辑/审计归档，由 `.gdignore`
  排除在 Godot 导入之外。
- 场景、脚本和资源间只使用 `res://` 引用；不得使用机器绝对路径或上级目录。
- 像素贴图默认 nearest，除非单项资产明确要求，不开 mipmaps。

## 5. 场景与路由

```text
boot.tscn
  → camp.tscn
      → map.tscn
          → combat.tscn
              → map.tscn / camp.tscn
```

- 场景切换通过 `Game.goto_scene()` 完成。
- 长生命周期状态放在 `Game` autoload，不用隐藏常驻场景伪装全局服务。
- UI 页面优先使用 `Control` 容器、anchors 和 offsets；不将业务状态存在节点可见性中。

## 6. 营地与经济

- 营地全景使用 `ScrollContainer`，HUD 保持在滚动容器之外。
- 建筑位置、名称牌和状态标记均使用 Godot 逻辑像素，不在运行时换算旧引擎坐标。
- 灵源院产出与容量从 `data/config/ling_pu_config.json` 读取，结算通过 `Game`
  事务方法修改 profile，然后发出 `state_changed`。

## 7. 方格地图、迷雾与 Dual Grid

- 逻辑移动只允许上下左右；地图坐标与画面 Y 轴翻转由 `map_canvas.gd` 集中处理。
- 迷雾状态为 `UNKNOWN → DISCOVERED → VISIBLE`，存档保存已探索和当前位置。
- Map01 只保留 `assets/maps/map_01/map01_background.png` 作为正式视觉；基础可走格、困难格和阻挡
  直接读取 `data/maps/map_01_formal.json`，不保留 D0 tileset 或 TileMap 回退。
- Dual Grid 固定为四角掩码 `0x1–0xF`，完整块 `0xF` 是编辑器绘制入口。
- 地图结构、POI 和碰撞规则参见 [`05_地图与关卡编辑方案.md`](05_地图与关卡编辑方案.md)。

## 8. 战斗

- 固定时间步更新战斗进度，不让帧率改变结算结果。
- `combat_resolver.gd` 只计算目标、伤害、治疗和事件；`combat.gd` 负责输入、时序、绘制和结算界面。
- 演出、粒子或动画不得决定是否命中或何时写存档。

## 9. 存档与版本

- 存档位于 `user://kunwu_profile.json`，使用临时文件写入后再原子替换。
- 读档时先合并 `default_profile.json` 的默认字段，再校验关键类型与范围。
- 测试或无界面验证不得覆盖用户的真实存档。
- 如果 Schema 变更，为每个历史版本保留单向迁移函数，不回改已发布迁移快照。

## 10. 动画、特效与音频

- 序列帧使用 `AnimatedSprite2D`/`SpriteFrames` 或 `AnimationPlayer`。
- 2D 特效使用 `GPUParticles2D`、`CPUParticles2D`、`ShaderMaterial` 和 `CanvasItem` shader。
- 高频特效可池化；所有一次性节点都必须有最长生命保险。
- 音频通过 `AudioStreamPlayer`/`AudioStreamPlayer2D` 和项目 Audio Bus 管理，不由规则层直接播放。

## 11. 性能预算

- 375×817 视口目标稳定 60 FPS；低端移动设备可降级至 30 FPS。
- 地图只更新可见格、迷雾边缘和活动对象；不每帧遍历整张 `28×64` Map01。
- 避免在 `_process`/`_draw` 中重复 `load()`，需要的贴图使用 `preload()` 或缓存。
- 大型原始资产保留在 `.gdignore` 归档，运行时只保留裁切/压缩后副本。

## 12. 验证策略

1. JSON 和 `res://` 静态路径检查。
2. `Godot --headless --editor --path <project> --quit` 导入与脚本解析。
3. 主场景无界面加载。
4. 领域规则脚本测试和专用验证工具。
5. 在 Godot 编辑器中人工验收视觉、触控、横滑、迷雾和 Tile 接缝。

## 13. Definition of Done

- 新代码、场景和资源只使用 Godot 4.7.1 兼容 API 和 `res://` 路径。
- 无上级工程、无网络时仍可导入并运行当前闭环。
- 数据改动有规则校验，场景改动有无界面加载验证，视觉改动有人工验收入口。
- 不提交 `.godot/` 缓存、导出产物、机器绝对路径或客户存档。
