# 高清地图与外部标注接入规范

2026-09-09：用户确认高清古道 Demo 的底图、标注对齐和实际碰撞接入效果，并要求作为后续同类地图的规范。

## 适用范围

后续收到“高清整图 + 外部编辑的碰撞/调节层 JSON + Godot 导出”时，默认沿用本流程，无需重新讨论已经确认的接入方法。具体地图的素材、玩法和特殊图层语义以当次用户交付为准；不强制所有地图采用整图，也不自动替换既有正式 Map01 的格子、对象和互动契约。

## 素材与数据事实源

- 底图、导出清单和标注必须来自同一批导出。优先使用清单引用的配套原图，记录尺寸、坐标系、相对路径和区域数量；不能拿外观相似的旧图、缩略图或另一裁切版本代替。
- 首先检查 JSON 的 `canvas`、`coordinate_system`、`annotations.layers`、各层 `id` 和 `shapes[].points`。当前 Pixelwork 导出为左上原点、Y 向下的像素坐标；后续必须读取当批声明，不能硬编码本次尺寸。
- JSON 中的人工标注是区域事实源；TSCN 用于交叉核对节点、变换和资源引用，不能因为渲染出错就认定 JSON 没有配置。若两者不同，先定位版本或变换差异，不猜选一份。
- 保留所有原始轮廓和顶点，包括大面积山体、地图边缘和复杂多边形。不按面积过滤，不凭截图重画，不从底图像素识别可走区，不叠加旧手绘路线限制。
- 项目内保留可追溯的运行资源副本，运行不得读取 Downloads、候选目录、Docs 或上级工程。每张地图指定唯一有效的区域数据入口。

## 坐标与显示

统一坐标链：**导出像素 → 地图局部坐标 → 世界坐标 → 相机/屏幕坐标**。

无裁切、无偏移的整图中，`地图局部点 = 原始点 × (地图显示尺寸 / canvas尺寸)`。背景若存在居中、offset、裁切、父节点变换、旋转或缩放，必须将相应变换纳入同一映射；导航需要世界坐标时继续应用同一地图变换。

- 背景、碰撞、调节层及运行对象共享该坐标契约，不分别猜缩放系数。
- 相机缩放只改变视野，不重新缩放碰撞数据，不改变可走性。必须检查多档缩放下视觉边界与实际阻挡仍一致。
- 替换底图时重新核对配套关系；仅把外框缩到相同大小不能证明内部地标对齐。

## 区域语义与实际移动

- 当前约定：红色 `collision` 是不可进入区域；地图边界内、碰撞区外为基础可走区域。角色足底半径参与边界距离判定，防止角色中心合法但脚底越界。
- 紫色 `adjust` 是独立调节区域，不默认当作实体阻挡。遮挡、触发、状态与特殊地形按明确语义单独接入，不能用显示颜色推断业务。
- 键盘、触屏、连续移动、点击寻路与路径简化必须共用同一可走判定。不得只接入 Debug Overlay 却仍让旧走廊控制移动。
- 连续移动做分步阻挡或等价的连续碰撞检测；寻路路径段也要检测穿越，避免大步、斜角或细窄边界穿透。
- Debug“路线/可走区”显示真实导航结果。临时编辑可以增加或撤销附加禁行，普通恢复不能覆盖源碰撞。源区域修改须明确写回指定地图数据；不得静默读取旧缓存覆盖新交付。
- 导入失败或缺少区域数据应明确报错，不可悄悄放开整图或回退到旧路线。

## 复杂轮廓

不得因 Godot 三角剖分失败而删除区域、改变点序或用凸包扩大碰撞。当前已验证方案使用奇偶规则解释自交轮廓，显示用顶点/交点分带填充，实际移动用同义点内及边缘距离判定。后续若源编辑器使用不同填充规则，先核对并适配；技术修复须保持用户编辑的区域语义。

## 交付验收

1. 核对配套底图、canvas、区域数量和全部原始顶点，确认没有遗漏、过滤或擅自改写。
2. 检查地图角点、中心、山体边缘和石柱等内部地标；逐点比较显示与移动坐标，并覆盖默认、最小、最大及 Debug 缩放。
3. 验证出生点与目标合法、关键地标可达；沿实际寻路路径逐步移动，检查红区点击拒绝、贴边、大步、斜向和地图外边界阻挡。
4. 切换 Overlay 显隐或镜头缩放不得改变碰撞；Debug 恢复不得涂穿源红区。
5. 执行相应 Godot 导入/加载、自动验证与实机画面核对。测试使用 `--no-profile-write --ignore-config-cache`，不覆盖用户档案。
6. 分别说明“显示已对齐”和“实际移动/寻路已接入”的验证结果；仅完成前者不能称素材整批应用完成。给出用户操作复核入口。
