# 营地制作复盘与野外地图参考

日期：2026-09-24。依据：本任务用户逐轮反馈、当前实现和验证记录。用户已确认营地达到相对满意的结果，本文记录可复用经验，不代表所有参数已成为全项目标准。

本文不是新的玩法事实源，也不自动迁移正式 Map01。产品范围仍按策划 → PRD → 实现；同类整图地图遵循[高清地图与外部标注接入规范](高清地图与外部标注接入规范.md)，生成素材遵循[地图生成式美术生产与模型分工规范](../ArtAssets/18_地图生成式美术生产与模型分工规范.md)和[Meowa API 调用规范](Meowa_API调用规范.md)。

## 一、最终形成的制作方式

**可编辑的地形与独立物件 + 经过确认的静态美术 + 局部循环动画 + 独立碰撞/交互数据 + 受限玩家镜头。**

营地不是一张烘焙好所有内容的图：建筑、传送阵、装饰、角色、流水和雾有各自职责。编辑器能够看全图、调整摆放；玩家只能看到放大的局部，使用 WASD 或点击寻路，靠近建筑/NPC 按 E 交互。原有 HUD 和业务面板继续使用。

## 二、实际制作过程与关键决策

| 阶段 | 本次做法与调整 | 留给下一张地图的经验 |
|---|---|---|
| 确定风格 | 原 3D 建筑不合适，以用户提供的炼器坊序列帧为起点，重做其他建筑静态候选 | 先定一个代表性素材；同时检查真实显示尺寸、视角、光照、像素密度和色调 |
| 建筑逐个确认 | 议事殿反复增强宏伟感；灵源院增加水轮；按摆放位置确定朝向，合适时水平翻转 | 同风格不等于所有建筑同轮廓、同体量或同朝向；地标须有辨识度，门口要朝向可到达区域 |
| 静态转动画 | 用户确认静态候选后，再调用 Meowa 制作建筑循环序列帧 | 先冻结主体结构和锚点，再做动画；避免在结构尚未满意时付费反复生成 |
| 动画接入 | 透明素材、帧图集、SpriteFrames 和播放参数接入 Godot；逐座放入编辑器检查 | 单独预览好看不够，要在地图内检查脚底、大小、遮挡、循环接缝和闪跳 |
| 补充环境 | 用少量装饰增加层次，加入阵旗、阵灯、魂龛；传送阵回到原版结构，保留可动画的光柱 | 普通装饰优先复用；重要功能地标应一眼可识别，不必每个物件都生成动画 |
| 右侧山水 | 从刻意延伸/接水的方案，调整为灵源院背后的自然瀑布，向下汇入现有溪流 | 环境要有空间和流向逻辑；先解决山、水、建筑的关系，再加动态 |
| 角色 | 复用已有免费 NPC 素材包，三位角色漫游，再选独立外观作为玩家角色 | 先检查资源库和已有动作，避免重复生成；角色脚底锚点和地图尺度统一 |
| 底部流雾 | 从过淡、忽隐忽现改为持续横向流动的厚雾，覆盖整屏宽度，拖动时仍遮住下方悬崖 | “流动”与“透明度闪烁”不同；背景氛围的覆盖必须在极端镜头位置验收 |
| 阶梯美术 | 阶梯改为灰青旧石材质，复用铺地纹理，不重新生成整套图 | 风格小修优先确定性调色、材质处理；不必每次新增位图 |
| 正式化 | 复用 Demo 视觉、布局和原建筑业务；用户纠正后恢复原 UI，取消全景入口 | 用户认可场景视觉不等于认可重做 UI；正式化必须核对原系统与返回流程 |
| 玩家视角 | 默认局部放大、有限缩放；根据截图确定左右边界，下限再精确为传送阵底部以下 15px | 用玩家视角确定镜头边界，不能把编辑器适应全图的镜头当正式镜头 |
| 操作与交互 | 点击行走、WASD、镜头跟随；建筑/NPC 近距离 E 提示；弹窗阻止移动 | 输入方式、导航、镜头、交互范围必须一起验证 |
| 碰撞与遮挡 | 清理建筑移动后残留的旧占格；建筑碰撞随当前美术变换；脚底 Y 排序；编辑器开放碰撞与遮挡设置 | 美术摆放完成不等于碰撞完成；可视化轮廓及可调参数应早于细节打磨 |

本次用户曾明确允许直接使用内置生图工具制作静态候选；这是本次授权，不应自动改写其他任务的默认供应方规则。Meowa 的每座最多 30 点等属于批准上限，不能当作实际扣费；实际消耗以各 Job 结果为准，后续地图须重新授权。

## 三、最重要的返工原因

### 1. 美术位置、碰撞、门口不一致

建筑可以按像素微调，但旧导航仍使用原始格子 `origin/footprint_size`。交易行美术移走后，旧占格仍压住 `[8,2]` 阶梯，造成“看着是路却走不过去”。旧入口坐标也曾让 E 提示出现在远离当前门口的位置。

现在建筑用独立地基碰撞多边形，随当前门槛位置及变换更新，运行时、NPC 导航和编辑器校验共享实现。交互参考当前门槛与可达节点。

**后续要求：移动/缩放物件时，同时验证视觉、碰撞、遮挡排序点、交互位置和可达入口。** 不要将透明 PNG 外框或屋顶轮廓直接当作地面碰撞。

### 2. 格子中心能连通，不代表角色能自由走

WASD 沿屏幕方向移动会穿过菱形格角点，旧四邻格判定会误挡；以欧氏距离判断所属格也会留下错误归属。修正后按实际包含区域更新所属格，允许同平台且两侧均畅通的对角通行，禁止切过障碍角。

阶梯另有高差，单根中心线不足以表示完整踏步宽度。当前补齐阶梯宽度和上下端连接。

**后续要求：测试平台内部、格边、格角、阶梯中心、两侧及两端；不要只验证寻路图里的现存边。** 被错误阻挡而直接消失的节点/边，必须对照作者定义检查。

### 3. 画面能动，不等于动画正确

雾的目标是保持浓度、持续横向流动，而不是周期性出现/消失。流水要有自然流向，建筑动画不应导致地基或门口漂移。

**后续要求：先明确运动对象和不变量。** 镜头固定、地基不动、角色足底稳定、光柱局部变化等，都要写入素材契约。

### 4. 镜头不能只限定中心点

固定中心范围在缩放后会露出不同数量的外围。改为约束可视世界边缘，再由视口大小和缩放计算中心范围。底部 15px 是逻辑屏幕像素，因此需随缩放换算，不能直接加到世界坐标。

**后续要求：区分世界坐标、逻辑屏幕像素和实际窗口像素；至少检查最小、默认、最大缩放及四边极限。**

## 四、后续野外地图的推荐生产顺序

1. **先定玩法与玩家视角。** 明确出生/出口、主支路线、交互点、战斗区、视角、角色尺寸和镜头限制。先用简单块面跑通，不从精修全图开始。
2. **选地图表现方式。** 整图背景配标注，或模块化地形配独立地标。根据是否需要频繁改地形、物件动态和遮挡选择，不因营地用了格子就强制所有野外用格子。
3. **冻结坐标契约。** 原点、尺寸、显示比例、门口/脚底锚点、层级、碰撞与调节区语义写进该地图清单。整图和 JSON 必须为同批导出。
4. **先完成一个代表性局部。** 地面、山石/树、一个地标、一条高差通路、一名角色和一处互动同时存在。先在最终玩家倍率下确认风格与移动。
5. **静态资产优先。** 复用已确认素材，本地处理能完成的先本地做；必要的新素材逐个生成、放进场景确认。用少量重复装饰形成层次。
6. **同步配置实体与遮挡。** 从第一个地标开始就设置地基碰撞、遮挡基准和互动点；提供真实区域 Overlay，避免等美术完成后重画整张导航。
7. **最后增加必要动画。** 按关注度优先做水、火、传送/灵力、关键地标，再考虑普通环境；先冻结静态轮廓再提交付费生成。对规则性运动优先评估本地序列帧或 shader。
8. **统一移动与交互。** WASD、点击寻路、NPC、路径简化共用可走语义；不允许只画对 Overlay 而实际走另一套旧路线。
9. **接入镜头与 UI。** 保留既定 HUD；实现跟随、拖动、缩放边界和弹窗拦截。关卡氛围雾、探索未揭示迷雾分开实现。
10. **实机验收后晋升。** 默认视角、边界、地标接触、遮挡、路线、地图进出和存档都通过；保留素材、配置、脚本、验证入口及用户确认记录。

## 五、素材和对象的最小交付契约

| 类别 | 必须记录 |
|---|---|
| 静态图 | ID、用途、来源/使用条件、原始尺寸、透明通道、视角/朝向、实际显示宽度、锚点、候选/批准状态 |
| 序列帧 | 输入静态版本、帧尺寸/数量/排列、FPS、循环规则、共同锚点、透明边缘、是否镜像、原 Job/结果引用 |
| 可摆放物 | 位置、旋转、缩放、地基碰撞、碰撞开关、遮挡开关/排序基准、互动点、可达入口 |
| 地图 | 底图/模块清单、坐标与变换、边界、出生/出口、独立区域数据、镜头范围、正式入口 |
| 验证 | 原始数据一致性、实际行走与寻路、不同缩放、极端边界、交互闭环、截图和用户反馈 |

本次建筑配置参考：`collision_enabled`、`collision_polygon`、`collision_reference_width`、`collision_scale`、`occlusion_enabled`。当前碰撞初值是可调的地基菱形，不代表复杂野外物体也应统一成菱形。树冠、桥梁、洞口、可穿过建筑等需按各自语义拆分。

## 六、哪些可以复用，哪些不能照抄

| 可以复用 | 需要按地图重新确定 |
|---|---|
| 单个静态确认 → 局部动画 → 实装验收 | 野外的视角、色盘、地标轮廓和危险区域表现 |
| 原图与候选留档、透明和锚点检查 | 世界尺寸、资源分辨率、帧数/FPS、资源预算 |
| 可编辑碰撞轮廓、门口/脚底基准、前后排序 | 树冠/悬崖/桥梁等复杂遮挡与实际碰撞形状 |
| 受限相机、平滑跟随、原 HUD 保留 | 镜头倍率、边界、底部留白；营地 1.0～1.35 倍和 15px 不是通用值 |
| 小步移动检测、路径段检测、多输入一致性 | 具体导航实现；营地 AStar2D 格图不替代正式 Map01 标注导航 |
| 三档缩放、四边、侧缘、交互及场景闭环测试 | 野外探索迷雾、战斗触发、资源采集、地图状态等玩法 |

底部流雾是营地美术遮盖层，不能拿来替代野外探索迷雾。整图地图按外部原始 JSON 接入，不从图像像素反推碰撞；也不恢复已归档的 Map01 Dual Grid 方案。

## 七、本次工程参考入口

- `scenes/camp.tscn`、`scripts/scenes/camp_landscape.gd`：正式营地、原 UI 复用、局部视角、玩家输入、跟随和 E 交互。
- `scripts/scenes/camp.gd`：原有建筑业务和面板。
- `data/prototypes/camp_tile_rebuild.json`：正式营地与编辑器共享布局；历史目录名不表示另一份 Demo 数据。
- `scripts/prototypes/camp_tile_rebuild.gd`：地形、阶梯、建筑、图层与导航组装。
- `scripts/prototypes/camp_collision.gd`：建筑地基碰撞及路径段判定。
- `addons/camp_layout_editor/`：摆放、微调、碰撞/遮挡设置、轮廓预览、保存与撤销。
- `scripts/prototypes/camp_npcs.gd`：复用角色与漫游。
- `scripts/prototypes/camp_stream.gd`、`camp_mist.gd`、`camp_stair_stone.gdshader`：流水、流雾和阶梯材质。
- `tools/build_camp_mist_sequence.py`：本地确定性循环雾序列。
- `tools/validate_camp_controls.gd`、`validate_formal_camp.gd`：行走/交互和正式场景回归；另有雾、NPC、传送阵专项验证。

验证使用 `-- --no-profile-write --ignore-config-cache`。另一正常游戏进程可能同时写存档，磁盘字节变化需要区分来源，不能为了测试回写旧存档。

## 八、当前结论与剩余边界

本轮记录的验证包括：404 个平地对角案例、全部现存导航边、四段作者定义阶梯的完整性、24 次阶梯侧缘双向通行、建筑内部阻挡、E 交互、八建筑入口及出征归营；Godot 导入和编辑器碰撞控件/撤销通过。

这些测试证明对应操作契约，不等于整张地图已完成逐像素碰撞验收。当前编辑器仍能报告局部不可达格；例如招贤馆后侧有两个可走节点与主路断开，后续若要求进入该处，需要结合建筑轮廓和关卡意图调整，不能只消除警告。NPC 当前是漫游和简单寒暄，不等于完整任务系统。

用户本次确认应作为后续视觉参考基线；野外制作时仍需在真实玩家视角确认一段可玩的样板区域，再扩大生产。
