# Godot 4.7.1 编辑器操作清单

本清单只记录当前 `KunWuGodot` 工程需在 Godot 编辑器中人工确认的步骤。旧引擎操作已封存到
[`LegacyCocos/09_编辑器操作清单.md`](LegacyCocos/09_编辑器操作清单.md)。

## 1. 首次导入

1. 打开 Godot 4.7.1 项目管理器。
2. 导入项目根目录的 `project.godot`。
3. 等待右下角资源导入完成，不在首次扫描中运行项目。
4. 在 Project Settings 检查：
   - 视口 `375×817`；
   - Stretch Mode 为 `canvas_items`；
   - Renderer 为 `gl_compatibility`；
   - Default Texture Filter 为 nearest。

## 2. 项目启动

- 按 `F5` 运行整个项目，主场景应为 `res://scenes/boot.tscn`。
- `F6` 只用于调试当前独立场景，不用它替代整体流程验收。
- 启动后应可依次进入：启动页 → 营地 → 入山整备 → `map_01` → 战斗 → 归营。

## 3. 场景与 autoload

在 Scene 和 Project Settings 中确认：

- [ ] `Game` autoload 指向 `res://scripts/autoload/game.gd`。
- [ ] `boot.tscn`、`camp.tscn`、`map.tscn` 和 `combat.tscn` 可单独打开，无丢失脚本。
- [ ] 场景切换只走 `Game.goto_scene()`，节点不持有跨场景野指针。
- [ ] 场景、贴图、字体和 JSON 引用均为 `res://` 路径。

## 4. Map01 正式地图

1. 打开 `res://scenes/maps/map_01.tscn`，确认只有 `HDBackground` 视觉节点。
2. 背景应为 `res://assets/maps/map_01/map01_background.png`，尺寸 `1344×3072`。
3. 可走、困难、阻挡、入口和对象坐标在 `res://data/maps/map_01_formal.json` 中编辑。
4. 不向 Map01 添加 TileMapLayer、TileSet、旧地标组件、Demo、Preview 或第二套候选数据。
5. JSON 坐标变化后用 `F5` 检查背景构图、迷雾、网格和 Marker 是否仍对齐。

## 5. 营地视觉验收

- [ ] 中间全景可横向拖动，顶部和底部 HUD 不随全景滚动。
- [ ] 建筑名称牌、锁定标记和关注标记位于建筑内预定位置。
- [ ] 灵源院、入山整备和议事殿面板在 `375×817` 视口内不裁切主要按钮。
- [ ] 贴图边缘不发糊，没有半像素抖动。

## 6. `map_01` 验收

- [ ] 只允许四方向移动，阻挡格不可进入。
- [ ] `UNKNOWN`、`DISCOVERED`、`VISIBLE` 三种迷雾状态可辨识。
- [ ] 移动消耗灵粮，碎石格消耗正确。
- [ ] 宝箱、故事、敌人和入口标记在迷雾中的显示规则正确。
- [ ] 退出并重新进入后，位置、已探索区和已处理对象可恢复。

## 7. 战斗验收

- [ ] 四名修士可切换自动/手动。
- [ ] 行动就绪、冷却、伤害、治疗、撤离与战利品流程可见。
- [ ] 动画或帧率波动不改变领域结算顺序。
- [ ] 战斗结束回地图后，对象状态和临时战利品一致。

## 8. 无界面验证

终端执行：

```bash
/Applications/Godot.app/Contents/MacOS/Godot \
  --headless --editor --path "/Users/zhangxiaoen/Desktop/Game/KunWuGodot" --quit
```

Map01 正式验证：

```bash
/Applications/Godot.app/Contents/MacOS/Godot \
  --headless --path "/Users/zhangxiaoen/Desktop/Game/KunWuGodot" \
  --script res://tools/validate_map01_formal.gd \
  -- --no-profile-write --ignore-config-cache
```

通过标准：进程退出码为 `0`，无 GDScript 解析、场景加载、缺失 `res://` 资源或插件错误。
无界面 dummy renderer 退出时的纯 RID/resource leak 提示需与真正加载错误分开记录。
