# 《昆吾禁地》动画制作规范

版本：Godot-0.6
形式：探索俯视像素动画 + 战斗动态立绘像素动画 + UI/场景轻动画

本章中的普通战斗修士序列帧规范是人物尺寸、裁切、锚点和动画交付的唯一口径。整备卡、战斗
底部单位槽和后续战斗页面均复用同一套 `86×205` 人物母帧；页面通过不同 Mask 裁切，不得另定
一套人物图片或非等比拉伸人物。

## 1. 动画目标

动画优先服务：

1. 战斗时机：何时出手、何时命中、何时可被打断。
2. 职业辨识：金刚禅修、五行法修、玄箓修、剑修四个初始职业有各自动作语言，筑基后进一步
   区分八条分支的防护、输出、控制或辅助职责。
3. 状态表达：受伤、控制、中毒、濒死、复活。
4. 氛围：营地有生活感，禁地有沉寂与不稳定。

不追求高帧数堆量，而追求关键 Pose、清楚预备动作和有重量的命中帧。

## 2. 动画形式选择

| 场景 | 方案 | 原因 |
|---|---|---|
| 方格探索 | 四方向 Sprite Sheet | 低成本、像素一致、易换装 |
| 半自动战斗 | 单方向动态立绘 Sprite Sheet | 技能可读、人物信息叠压在立绘底部、资产量可控 |
| 大型 Boss | 分层骨骼 + 局部序列帧 | 方便阶段变形和部件破坏 |
| 营地 | 局部循环帧 + Tween | 建筑烟火、旗帜、NPC |
| UI | Tween/AnimationPlayer | 响应快、无需大图 |
| 剧情 | 角色立绘切换 + 镜头推拉 | 避免制作大量演出动画 |

0.1 Demo 不引入 Spine 付费工作流。1.0 四个 Boss 若帧动画产能不足，再评估
Spine 的 Godot 运行时、`Skeleton2D` 或分层 `AnimationPlayer` 方案。

## 3. 帧率与帧数基线

### 3.1 探索角色

| 动作 | 方向 | 帧数 | 播放速度 |
|---|---:|---:|---:|
| Idle | 4 | 4 | 6 FPS |
| Walk | 4 | 6 | 10 FPS |
| Interact | 4 或复用 | 4 | 8 FPS |
| Alert | 1 | 4 | 8 FPS |
| Hurt | 1 | 3 | 12 FPS |
| Down | 1 | 6 | 8 FPS |

逐格移动总时长建议 0.16–0.22 秒，脚步动画与坐标插值同步。

### 3.2 战斗角色

标准战斗单位槽外框为 `86×205`。人物层与信息层是前后叠放关系，不是上下相加的两个互斥区域：

```text
86×205 单位槽 / 裁切窗口
├─ 后层：86×205 人物层（铺满整个单位槽）
└─ 前层：86×56 信息层（覆盖在 y=149–204）
```

当前 Godot 实现的外框是 `86×205`；信息暗衬为内缩后的 `84×56`，位于 `x=1, y=149`，姓名按钮
从 `y=145` 开始，视觉上会比暗衬再向人物区域覆盖约 `4px`。规范层仍按 `86×56 @ y=149` 记录，
这 `56px` 是叠在人物层上方的 UI，不从人物帧高度中扣除，也不得烘焙进人物 PNG。

#### 3.2.1 人物帧模板

每一帧都使用同一张透明 `86×205 @1x` 母帧，不按帧单独裁切。母帧负责保存人物完整的横向动作
轮廓，不要求纵向完整展示全身：下半身可以延伸到信息层后方，也允许在母帧底边被截断。

| 项目 | 规范 | 说明 |
|---|---|---|
| 母帧画布 | `86×205 @1x`，RGBA 透明 | 人物层与战斗单位槽同尺寸；信息 UI 仍是独立前景层 |
| 横向构图 | 人物、服装和随身器物的必要轮廓全部收在 `x=2–83` | 战斗页必须完整显示横向轮廓；大范围法术拆到独立特效层 |
| 水平基准 | 躯干视觉中心约 `x=43` | 同一套动作保持一致；挥出的武器可以改变整帧视觉中心，但不能逐帧移动人物底图补偿 |
| 纵向构图 | 优先保证头部、双肩、手势和职业器物在 `y=0–144` 可读 | `y=149–204` 会被信息层覆盖；不为了露出脚而缩小人物 |
| 上方安全区 | 头饰和头顶不得贴边 | 具体留白由人物头身和动作决定，四名修士并排后统一验收 |
| 下方裁切 | 允许在腰、胯、大腿或衣摆处截断 | 脚底不是战斗母帧锚点，不要求完整全身进入画布 |

四名修士的视觉尺度不再用“完整人物高度”校准，而使用头部大小、肩线高度、躯干宽度和上半身视觉
重量校准。禅修可以更宽、更厚，剑修可以更窄、更轻，法修的法盘和符箓也可以形成不同剪影；但
不能因为某个职业天生较宽，就把整个人物缩小到显得矮一档。验收时并排比较四人的 Idle 第 1 帧，
并以 50% 透明度叠放检查头顶和肩线；明显大或小一档的角色退回统一缩放，不修改页面槽位。

`1024×1536` 等高清图片只作为清稿母版。处理顺序固定为：

1. 去除白色/灰色背景和上下无效留白，保留原始母版归档；
2. 对整套动作取共同内容边界，不能每帧单独裁切（否则人物会抖动）；
3. 先按头部、肩宽和必要器物确定整套动作唯一的等比缩放倍率；
4. 水平居中放入 `86×205` 透明画布，完整保留横向轮廓；纵向按上半身构图裁切，不强求露出脚；
5. 检查头顶、肩线、手势、横向安全区和信息层遮挡后导出图集。

禁止拉伸、压扁、逐帧单独缩放，或为了完整露出脚而把人物整体缩小。人物、衣袖或职业核心器物
横向超出安全区时，优先微调同一动作的等比缩放或把大范围法术拆到独立特效层。现有素材不因
本规范发布而自动重做。

固定网格图集规格如下：8 帧为 `344×410`（4 列 × 2 行），10 帧为 `430×410`（5 列 × 2 行）。
两种规格均按从左到右、从上到下编号；同一动画集不得混用紧密图集和固定网格。

#### 3.2.2 两个页面的裁切规则

| 使用位置 | 外框/Mask | 人物母帧显示规则 |
|---|---:|---|
| 入山整备修士卡 | 卡片 `71×163`；人物 Mask `45.517×139.31` | `86×205` 母帧保持战斗页的人物尺度，以躯干中心水平居中；人物层相对 Mask 使用 `x≈-20.24, y=-4.88`，左右各裁约 `20.24px`，下半身由 Mask 截去 |
| 战斗底部单位槽 | `86×205` | 人物层完整铺满 `86×205`；宽度方向必须完整展示人物必要轮廓，高度方向允许截去下半身；`86×56` 信息层覆盖在底部 |

两处使用同一帧序、同一人物尺度和同一人物身份，不分别制作“整备版”和“战斗版”。整备页通过
窄 Mask 取中间部分，战斗页使用母帧完整宽度；允许页面使用不同的纵向位置偏移，但不允许为适配
窄卡将人物横向压窄，也不允许为战斗页露出全身而缩小。

首领逻辑框最大 `172×256`，继续按部件或动作拆图集，不套用普通修士的 `86×205` 限制。

| 动作 | 帧数 | 速度 | 备注 |
|---|---:|---:|---|
| Idle（默认） | 8 | 6–8 FPS | 头部位移不超过 1px，肩、袖或衣摆位移不超过 2px；至少有 3 个可辨识变化 |
| Idle（长版） | 10 | 8 FPS | 当原始动作有完整的收势阶段时使用；使用 `5×2` 图集，不删帧、不补空帧 |
| Cast A | 8 | 10–12 FPS | 快速单体或普通攻击公共起手 |
| Cast B | 8 | 10–12 FPS | 蓄力、群体或重击公共起手 |
| Cast C | 8，可选 | 8–10 FPS | 防护、治疗或持续引导；确有剪影差异时制作 |
| Hurt | 不制作人物帧 | — | 由位移、闪白和命中特效表达 |
| Block | 不制作人物帧 | — | 由护盾/符阵特效和短促缩放表达 |
| Death | 不制作人物帧 | — | 人物变暗/淡出，魂火使用独立特效 |
| Revive | 不制作人物帧 | — | 人物淡入，复苏使用独立特效 |

普通修士的基础人物包因此为 `Idle + Cast A + Cast B`，职责确有需要时再增加 `Cast C`；三个技能
可以复用这 2–3 套人物动作，通过技能图标、事件时序和独立特效区分。Boss 动作可增加到
12–18 帧，但单个普通技能演出不超过 1.2 秒。

## 4. 职业与筑基分支动作语言

每个职业阶段固定三个技能。动画资源按“炼气职业公共动作 + 筑基分支差异动作 + 技能特效”
组合，避免四个初始职业与八个筑基分支全部从零制作。

### 金刚禅修

- 初始：赤足宽站、徒手结印，掌击强调肉身重量；金刚怒目用正面定身 Pose 和胸前掌印表现
  嘲讽，不使用盾牌或西式重甲。
- 护法金身：重心稳定、受击位移小；狮吼震心强调胸腔发力，镇狱掌印短促下压，金轮反照
  必须从受击动作自然衔接反震。
- 魔相力士：动作前倾、贴身爆发；魔纹开体增加呼吸与肌肉脉动，三相轰杀只用短暂臂影，
  筑基阶段不出现完整三相法身。

### 五行法修

- 初始：法盘、法镜悬浮，手势以牵引五行和归元收拢为主；不使用法杖。
- 雷法术式：起手短、命中突然，雷链需要以手势或法盘转向清楚表达多目标跳跃与群体减速。
- 蜃景幻法：动作舒展而内收，镜花惑心使用镜面错位，蜃雾蚀神用持续引雾动作，夺念还元
  以从目标回吸自身结束。

### 玄箓修

- 初始：手势短而精确，朱砂符匣、法印和符纸长带负责大幅次级运动；恢复使用经脉符纹，
  不使用圣光、祈祷或药师动作。
- 镇幽符脉：镇幽符宝为单点掷符，诛邪符阵以地面镇纹展开，安魂回元箓以群体符纹回流收势。
- 万象符脉：破灵符矢保持单体直射；六甲增元箓只连接一个恢复目标；力士符傀必须表现
  “符纸折叠成傀—临时生命外壳闭合—傀儡引敌”三个阶段。

### 剑修

- 初始：以剑匣和神识御使飞剑，飞剑点星、剑光分化、养剑诀分别使用单点、分光和回匣蓄养
  动作，人物不直接持剑挥砍。
- 青冥剑修：全程剑不入手，重心轻、起手短；分光追影用连续飞剑残影，剑煞归流表现剑光
  回旋与蚀痕汇聚。
- 玄岳剑修：改为双手持重剑，重心低且收招慢；玄岳破甲强调单点停顿，剑脊震岳为低伤震击，
  横剑断山用势大力沉的大幅群体横斩。

### 4.1 三技能动画复用规则

- 同一职业节点的三个技能必须至少拥有不同起手剪影。
- 同一初始职业的两个转职分支可共享 Idle、Hurt、Death，但 Attack/Cast 至少重制 2 组。
- 技能变化不能只靠换特效；青冥飞剑与玄岳重剑必须在人物是否持剑、重心和收招速度上直接可辨。
- 结丹沿用筑基分支的骨架与基础帧，只增加名阶强化后的关键 Pose 和特效层，不重做第二套三技能动画。

## 5. 动画状态机

### 5.1 探索

```text
Idle
├─ Move → Walk → Idle
├─ Interact → Idle
├─ Alert → Encounter
└─ Down
```

### 5.2 战斗

```text
Idle
├─ Attack/Cast → Recover → Idle
├─ Block → Idle
├─ Hurt → Idle
├─ Disabled → Idle
└─ Death → Dead
Dead → Revive → Idle
```

战斗模拟拥有状态真值，`AnimationPlayer`/`AnimatedSprite2D` 只负责表现。动画结束事件不能决定技能是否造成伤害。

## 6. 事件标记

每个攻击动画至少标记：

- `windup_start`
- `cast_commit`
- `projectile_spawn` 或 `hit_frame`
- `recover_start`
- `animation_end`

其中伤害由战斗模拟在 `cast_commit` 后安排；表现事件对齐 `hit_frame`。战斗页面只提供
正常速度；即使动画因卡顿、跳帧或降级播放缩短，结算顺序也不得改变。

## 7. Aseprite 制作规范

### 7.1 图层

```text
guide
body_base
clothes
hair_headgear
weapon_back
weapon_front
fx_reference
shadow
```

- `guide` 和 `fx_reference` 不导出。
- 探索角色的脚底锚点在所有帧保持一致；战斗人物改用头部、肩线和躯干中心作为稳定基准。
- 阴影独立，探索与战斗可以在引擎里统一生成。
- 标签命名：`idle_s`、`walk_n`、`attack_01`。

### 7.2 导出

- PNG RGBA。
- 无边距紧密图集或固定网格二选一；同一动画集不得混用。
- Sprite Sheet 必须带 JSON 帧信息或在文档中注明格子尺寸。
- 禁止导出缩放过的抗锯齿版本。

## 8. Godot 4.7.1 导入

### 8.1 普通 Sprite Sheet

- 项目默认使用 nearest texture filter，像素资源不开 mipmaps。
- 图集边缘使用 Clamp；需平铺的 Tile 由 TileSet 单独配置。
- 固定网格序列帧使用 `SpriteFrames` + `AnimatedSprite2D`。
- 需多轨、节点属性或事件轨的动画使用 `AnimationPlayer`。
- 动画资源按角色保存为 `.tres` 或随 `.tscn` 管理，不在每次播放时重建逐帧资源。

### 8.2 AnimationPlayer 与 Skeleton2D

适用于：

- 大型 Boss 分层骨骼。
- 带多个装备挂点或转职覆盖层的战斗角色。
- 需要混合或多轨道控制的动画。

标准 `86×205` 动态人物母帧优先 `AnimatedSprite2D`，只在需要部件变形、混合或多轨控制时使用
`Skeleton2D` 和 `AnimationPlayer`。

## 9. 换装与挂点

Demo 只实现武器和背部法宝挂点：

- `hand_main`
- `hand_off`
- `back`
- `head_fx`
- `body_fx`
- `foot_fx`

1.0再增加衣服分层换装。像素角色如果每帧挂点抖动，可为动画帧保存挂点表：

```json
{
  "attack_01": [
    {"hand_main": [18, 22]},
    {"hand_main": [20, 20]}
  ]
}
```

## 11. 场景动画

### 营地循环

- 旗帜：8 帧，8 FPS。
- 炉火：6 帧，10 FPS，随机起始帧。
- 炊烟：粒子而非大序列帧。
- 杂役：短距离巡逻 + 3 种停留动作。
- 建筑升级：局部脚手架消失、屋檐/灯火逐级增加。

### 禁地

- 石门：分三段开启，0.8–1.2 秒。
- 法阵：符文逐点亮，循环 1.5–3 秒。
- 宝箱：锁断、盖开、光溢出。
- 机关：动作必须早于伤害。
- 传送：角色先溶解，再触发场景切换。

## 12. 剧情演出

1.0使用轻量演出模板：

1. 背景立绘或像素场景。
2. 角色半身剪影/头像。
3. 镜头平移、推近、轻震。
4. 关键物件特写。
5. 少量表情替换。

不制作长篇逐帧动画。单段不可跳过时间不超过 3 秒，完整对话可快进、可回看。

## 13. 动画性能

- 同屏非战斗环境动画不超过 25 个。
- 离屏 Sprite 动画组件暂停。
- UI 不可见时停止 Tween。
- 大 Boss 分层不超过 12 个 Sprite。
- 动画贴图按章节加载，返回营地时释放。
- 角色图集单张优先控制在 2048×2048 内。
- Web 首发按职业和地图拆分图集，不把四个初始职业与八个筑基分支全部打进首屏加载包。

## 14. 动画交付清单

每套动画需要：

- `.aseprite` 或等价源文件。
- Sprite Sheet PNG。
- 帧数据 JSON。
- 动画列表和 FPS。
- 命中/发射事件帧。
- 锚点与挂点表。
- 10 秒预览 GIF/MP4。
- 许可与作者信息。

## 15. 验收标准

- 探索角色四方向脚底不滑。
