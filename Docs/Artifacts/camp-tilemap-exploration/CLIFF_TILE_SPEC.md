# 营地岩壁瓦片集：接口规格 v1

最新范围覆盖：连续台地美术与边界职责以 CONTINUOUS_TERRAIN_CONTRACT.md 为准。下述144×128单元仅为历史几何样板，不代表已确认L图可直接裁为这些瓦片；“地面仍用原图集”及分开生成A/B的旧美术路线已废弃。

状态：几何规格与技术样板已实现；现有A/B美术候选在art/candidates/camp-cliff-tiles/gpt-v1/，尚未批准。规格本身不是最终美术。
本规格替代 ROCK_ART_PROPOSAL.md 的“先生成一块大岩壁再适配”方案。
范围只到固定斜俯视正交镜头下的岩壁瓦片；地面仍用原图集，岩壁不使用地面四角掩码或47-piece规则。

## 1. 坐标与统一画布

| 项目 | 冻结值 |
|---|---|
| 地面逻辑格 | 128×64 |
| 平面轴 | +X=(64,32)，+Y=(-64,32) |
| 岩壁高度单元 | 48，允许48/96/144等叠高 |
| 单朝向立面有效包围尺寸 | 64×80，包含顶边投影产生的32像素高度 |
| 双面外角有效包围尺寸 | 128×80；整体保留128×112逻辑包络以兼容内角与顶/脚层 |
| 所有图集单元 | 144×128，逻辑包络四周各留8像素 |
| 统一锚点 | 图片坐标(72,40)，代表所属地面菱形中心 |
| Godot图集 | region=144×128，tile_size=128×64，texture_origin=(0,-24) |
| 精灵等效位置 | Sprite2D centered=false，位置=地面格中心−(72,40) |
| 过滤 | nearest，无mipmap；不得为对齐单独拉伸A/B |

144×128是图集存储单元，不是把地面格改大。Godot纹理偏移符号已通过真实TileMapLayer与Sprite逐像素对照，不靠猜测。
高台每叠一层，整片向屏幕上方移(0,-48)。顶沿仅最高层使用，崖脚仅最低层使用。

## 2. 首轮8种规格样板

| ID | 用途 | 局部边界与拼装 |
|---|---|---|
| wall_a | 左侧可见立面，顶边向右下 | (-64,0)→(0,32)，向下48；沿(64,32)连续重复 |
| wall_b | 右侧可见立面，顶边向左下 | (64,0)→(0,32)，向下48；沿(-64,32)连续重复 |
| convex | 朝屏幕的外凸角 | 同锚点A+B；替换两片直段，不再叠一套完整A/B |
| concave | 凹口内角 | B偏移(-64,-32)+A偏移(64,-32)，不得直接翻转外角 |
| rim_a / rim_b | 崖顶与地面衔接 | 6像素厚覆盖带，向台地内部延伸，不扩大可走面积 |
| foot_a / foot_b | 崖脚与下方地面衔接 | 最底4像素覆盖带，作为贴花，不形成额外高差 |

A/B颜色在样板里故意不同，用来查朝向；不是最终岩石调色。A/B的美术应在同一世界光源下分别制作，不镜像倒置光照。
内/外角样板目前验证两面的轮廓组合。最终美术要清理角线与纹理衔接；几何能组合不代表纹理已无缝。
顶沿和崖脚是装饰覆盖层，不替代立面本体；缺装饰时本体也不应露出透明孔。

## 3. 接口验收

- 横向：两片同朝向端部的Alpha和岩层/色调必须连续；样板已验证Alpha，纹理阶段另验收颜色。
- 纵向：中段顶部和底部的材质相位一致，禁止把苔藓崖顶、泥土缝或落地阴影烘焙到重复中段。
- 转角：从边集合识别凸/凹，再用角片替换对应边；不能把四角自动地形掩码套用到岩壁层。
- 深度：根据格坐标和高度排序；高处地面盖住岩壁顶缘，角色遮挡仍按独立逻辑处理。
- 轮廓：本轮样板使用像素中心判定与半开边界，不在同一条边重复拥有一列像素。
- 当前地图外侧额外22像素只是展示底座，不是通行高差。可从48立面按斜顶缘裁出22厚的遮罩；不得把整片缩短或拉伸。

## 4. 后续补片与当前边界

8种样板是基础集合，不宣称完整量产瓦片包。还需以下连接规格：

1. 孤立岩壁端头：A/B各自的两端，共4种；封闭台地目前不需单独端头。
2. 石阶：+X/+Y两个方向，各自上/下接口与两侧收口；沿用高差48与当前8级台阶。阶梯不复用直岩壁拉伸。
3. 水岸与落水口：另一个素材家族，不能挤入岩壁基础8片。
4. 至少两种直段纹理变化：保持端部接口一致，降低长墙重复感；等首套美术通过后再增加。

程序砌石/岩坡和全营地灰盒继续作为既有预览。本轮没有把技术色块导入正式营地，也没有宣称已完成自动岩壁笔刷。

## 5. 文件与复现

- `cliff-kit/spec-board.png`：8种规格与整块/凹口/叠高台地示意。
- `cliff-kit/blueprint-atlas.png`：576×256技术图集，4列2行；单片PNG在同目录。
- `cliff-kit/manifest.json`：画布、锚点、各片坐标、叠高与拼接规则。
- `cliff-kit/validation.json`：本地透明轮廓及朝向检查；Godot结果见`cliff-kit/godot-validation.txt`。
- `tools/build_camp_cliff_blueprint.py`：可重复构建图集/规格板并做9项Alpha/颜色组合断言。
- `tools/validate_camp_cliff_blueprint.gd`：仅离线验证工具读取规格图，非游戏运行依赖。Godot4.7.1实际渲染8片与精灵锚点逐像素相同。

这轮没有改游戏运行脚本、正式TileSet或布局数据。后续真正接入时，批准素材进入assets，绝不由游戏读取Docs。
