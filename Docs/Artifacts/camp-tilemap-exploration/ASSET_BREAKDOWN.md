事实源：营地美术分册01、通用事件标记分册07、地图美术生产规范18、当前背景与建筑PNG、camp.gd。

## 1. 现状与纠正

当前背景实际为 `assets/camp/env_camp_panorama_bg.png`，1422×1106；运行绘制框1152×896。
美术分册的1152×896是交付/显示设计口径，不能当成当前PNG原始尺寸。
七座建筑与传送阵已独立存在，正式营地不是把建筑全部烘焙在一张图上。
当前TileMap实验仅是交互技术样例，其平草地、规则砖路、池塘和32px网格均不是美术方案。
用户已确认横屏＋斜俯视正交，不采用近大远小；此前“弱透视”建议已废弃。精确俯角和朝向仍待校准，见STRUCTURE_PLAN.md。
若以后改为严格俯视，应另行评估整套建筑视角，当前复用判断不再成立。

## 2. 背景的实际空间结构

下列来自直接查看背景原图，不代表已提取图层或碰撞。

| 层次 | 原图可见结构 | 建议实现 |
|---|---|---|
| 极远景 | 冷青山峰、层叠云雾、细瀑布 | 少量大幅远景层；雾/瀑布独立效果，必要时轻微视差 |
| 中央地标 | 中上部高山与红色封印纹样 | 独立大型地标；山体与可变封印亮度分开 |
| 地形骨架 | 多个有明显高差的石台，前侧与侧侧崖壁 | 台面地形＋崖沿/崖壁模块，分别管理层级与逻辑高差 |
| 通路 | 不规则石铺路、裸土、石阶，上下台地之间的通道 | 可重复地形＋独立阶梯组件，布局单独定义 |
| 水系 | 狭长溪流穿过台地之间，局部落水与亮色泡沫 | 水底/水面＋岸线＋落差瀑流＋浪花，多层组合 |
| 边界装饰 | 石柱、红绳护栏、挂旗、路灯、小石碑 | 独立道具或可重复模块，可单独隐藏、摆动、点亮 |
| 破除重复 | 苔藓、碎石、草丛、松树、裂缝 | 少量变体贴花与独立树石，不做满地均匀噪点 |
| 前景 | 下侧和两侧的崖壁、树石与绳栏 | 独立前景；将来角色行走时再定义遮挡/淡出 |

原图中的“空地”是建筑落位用的台面，不能简单用草地替代。深浅、高差、通路和水系应先恢复，再讨论装饰密度。
远景和大型封印山体不必瓦片化；可控不等于每个像素都切成Tile。
整图只有最终合成结果，提取远景、栏杆或树后可能缺少被遮挡的像素；裁切不自动产生可无缝复用组件。

## 3. 瓦片与模块需求

数量按“家族”规划，不预先承诺最终Tile张数；连接规则、格子大小和透视校准后再展开变体。

| 优先级 | 家族 | 应覆盖的构件/情况 | 形式 |
|---|---|---|---|
| P0 | 风化岩土地面 | 基底、低频明暗变化、稀疏碎石变体 | 可重复地形 |
| P0 | 不规则石铺路 | 实心、窄/宽路、转弯、交叉、末端，与裸土的过渡 | 地形＋过渡边 |
| P0 | 台地边缘 | 正面/左右侧边、外角/内角、端点、不同宽度 | 模块化崖沿 |
| P0 | 岩壁立面 | 正面/侧面、纵向延展、顶部/脚部收口、破损变体 | 独立高差模块 |
| P0 | 石阶 | 正面阶梯、左右斜向连接、上下平台接口、侧边石护壁 | 多格场景组件 |
| P0 | 溪流与石岸 | 水底、水面、直段/弯道/窄口、岸线、落差口 | 地形＋水效组件 |
| P1 | 苔藓湿边 | 土/石/水岸附近的稀疏过渡 | 透明贴花 |
| P1 | 裂缝碎石 | 不同尺寸与方向，打破平铺重复 | 贴花/小道具 |
| P1 | 绳栏模块 | 石柱、直绳、转角、端点、台阶坡段、挂旗 | 独立模块 |

首轮只做“一处石台＋一段道路＋一道石阶＋一段溪流”，验证相接和高差后再扩展整个营地。
32px只是当前实验参数。先在817×375视口用同一建筑比较32/48/64逻辑格的占格与视觉密度，再定唯一格子规格。
不得把32/48/64任意缩放后混用为不同像素密度。建筑原始交付像素、显示尺寸与地形逻辑格需分别记录。
若选择Dual Grid，仅用于适合连续混合的地面材质；崖壁/阶梯不强塞进自动地形掩码。正式决定时加载对应技能。

## 4. Marker、道具与锚点分别是什么

| 类别 | 需要什么 | 复用/制作判断 |
|---|---|---|
| 状态Marker | 事件/可处理、锁定 | 已有 `icon_camp_building_attention.png` 和 `icon_camp_building_lock.png`，优先复用 |
| 状态Marker | 选中、当前目标、进度/倒计时 | 优先程序轮廓、光圈、文字或进度组件；不为每座建筑生成整套图片 |
| 装饰道具 | 灯笼、石灯、松树、石碑、石柱、旗帜、木箱/药篓 | 其中原图已有多种但烘焙在背景里；需要独立素材，不应叫UI Marker |
| 场景地标 | 中央封印山、传送阵、建筑 | 独立场景组件，保留稳定资源ID |
| Godot Marker2D | 门口、名称牌、状态图标、烟囱口、炉火、水口、遮挡参考点 | 无需绘制图片，只需统一锚点与坐标契约 |

如果营地未来允许角色行走，再补出生点、交互站位、台阶两端连接点和碰撞多边形；这些是逻辑数据，不从背景像素自动推断。
首轮不因地图制作而自动新增任务类型、收取规则或其他产品语义。

## 5. 建筑是否重做

判断原则：先保留造型，检查是否能拆层和重整底座，不因采用TileMap而整体重新生成。
本轮直接查看了背景、灵源院、炼器坊、传送阵原图；其他建筑的判断是基于现有独立资源与运行布局的初步分级，逐张技术检查仍待做。

| 建筑 | 当前判断 | 需要的后续工作 |
|---|---|---|
| 议事殿、招贤馆、百宝库、交易行、还魂殿 | 优先复用主体；暂不能宣称已完成逐张质量验收 | 检查统一视角、显示比例、轮廓透明边、台基与地形接口；灯光/门/遮挡按实际需要拆层 |
| 炼器坊 | 造型可保留，动态层必须处理 | 原PNG有固定烟团和炉火；做无烟/中性炉膛底图，再分烟、火、局部光。只叠新烟会出现双烟 |
| 灵源院 | 需要较多组件化工作 | 原PNG把建筑、三级药田、水车、流水、山石打包；至少拆水车/流水，若要田地状态可控则拆药田；主体房屋不必重做 |
| 传送阵 | 台座可保留，状态表现重整 | 原PNG有固定青色光柱；需无光静态台座＋阵纹发光＋光柱/粒子，才能真正关闭或切换状态 |

透明背景不等于内部各部件已经分层。直接抠出烟火/水车可能留下缺损；需要先检查隐藏结构能否本地修补，必要时才准备定向补图。
现有locked图片是既有素材，不能默认与开放态严格同锚点。未来状态切换前需对比尺寸、主体轮廓与台基位置。
每个建筑契约记录：显示尺寸、逻辑底面、落地锚点、入口锚点、名称/状态锚点、静态层、动态层、前景层；碰撞在行走范围明确后定义。

## 6. 建议制作顺序与验收

1. 冻结横屏镜头：保留三分之四视角，确定建筑显示尺寸、世界横向范围和上下层台地关系。先给布局草图，不扩写技术实验。
2. 做基准切片：一座现有建筑放到石台上，连接石阶、道路和溪流，配一盏灯。先保留无动态状态检查材质与结构。
3. 确定格子与模块规格：检查道路/台面/崖壁转角和接缝，统一像素密度、左上受光与接地阴影。
4. 只对有明确需求的建筑拆层：首选炼器坊或传送阵，验证关闭动效后没有残留静态烟/光。
5. 用户确认基准切片后，扩展全营地和更多变体；再做批量素材制作。

每阶段检查817×375实际视口：台阶是否真连接上下平台、建筑门是否接路、水是否沿岸连续、遮挡是否合理、贴图是否重复明显、建筑是否悬浮、动效能否独立关闭。
