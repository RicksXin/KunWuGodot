# 高清古道行走 Demo

入口：Godot 打开项目根目录 `project.godot`，F5 → 营地底部齿轮“设置” → “高清古道 · 行走 Demo”。也可打开 `scenes/map.tscn`，F6 直接运行。独立窗口使用项目根目录 `run_kunwu_game.command`，避免编辑器内嵌视图外框保持竖向。

- WASD / 方向键 / 按住屏幕箭头：连续行走，斜向速度归一化。
- 点击石路：避开不可通行区域寻路；按方向键随时接管。
- 滚轮或 −/+：普通运行：100%–150% 缩放，默认 120%；Debug 构建：14%–220% 自由调整；镜头持续跟随并限制在地图边界。
- 路线 / Tab：显示独立编写的通行走廊与阻挡，供视觉验收。
- 回到山脚：重置演示位置；返回设置 / Esc：回到营地并重新打开设置。

## 素材与实现边界

供应方为用户已生成的 GPT Image 原图；本次没有重新生成、裁切、改色或调用 Meowa，消耗 0 积分。用户提供并要求严格参照此图，本 Demo 直接使用其 1421×3071 RGBA 原始像素；图像 SHA256 为 `48e56b4cf34e3c1716541ce2f9df33afe0ec3b47cb17cdc7db9ed287151cef2e`。原始提示词未提供，不伪造。运行文件为 `assets/maps/mountain_walk/background.png`。

世界坐标为 897×1938.541（按新图比例等比显示），Sprite2D 按母图长宽比显示，高清背景使用 linear filtering。固定 2D 正交画布保留母图自身的偏俯视透视，不能旋转视角，不是 3D 地形。独立角色为 Godot 程序绘制的灰青衣修士占位，带步态、朝向、影子，视觉尺寸调整为初版的 65%；还不是正式高清行走美术。

实际通行由外部 `map01_hd_annotations_godot.json` 中36个碰撞多边形与地图边界决定；角色足底半径参与边界检测，键盘移动和点击寻路共用判定。已移除旧手绘走廊与圆形障碍。紫色调节层不作为阻挡，不读取背景像素。

本次新增 Demo 是用户明确请求的可行走演示，未替换正式 Map01、产品关卡或旧 landscape 预览；正式 28×64 JSON、背景、对象与战斗绑定保持原状。

## 关键文件

- `scenes/map.tscn`、`scripts/scenes/mountain_walk.gd`：入口、HUD、连续控制、镜头和场景返回。
- `scripts/maps/map_navigation.gd`：几何阻挡与 AStar 寻路。
- `scripts/maps/mountain_walk_actor.gd`：临时修士表现。
- `data/demos/mountain_walk.json`：路线及地标唯一事实源。
- `scripts/scenes/camp.gd`：设置入口与返回设置。
- `tools/validate_map01_formal.gd`：路径、长步阻挡、键盘移动、存档隔离、缩放、设置往返校验。

## 人工复核

进入 Demo 后沿左右路线从山脚走至山门，开启“路线”检查通行边缘与背景台阶是否贴合，确认修士比例和视角。2026-09-07 已换用用户重新生成的高清图；图片的树木、石栏也未拆分独立遮挡层。路线贴合与占位角色是后续视觉验收事项。此演示无正式战斗、资源采集与存档进度。


Debug 地图编辑：Debug 构建中点击顶部“编辑道路”，Shift 拖拽添加临时禁行，普通拖拽恢复原始通行范围，点击“保存”写入 `user://mountain_walk_debug.json`。该编辑仅作用于 Demo，不会修改正式 Map01、地图 JSON 或玩家存档。


Debug 高清标注预览：点击“碰撞层”显示36个红色碰撞区域及17个紫色调节区域。直接使用外部导出 JSON 中的原始坐标，配套底图为同一导出目录的 `images/overall/source.png`。标注与底图共享世界坐标缩放，修复此前整体约1.58倍过大的问题。

自交轮廓采用奇偶规则填充，不删除大范围区域。实际移动和点击寻路已使用相同JSON与坐标变换，“路线”显示真实寻路网格。此前“JSON不包含配置、必须依赖TSCN”的说明已废弃。

回归检查：`tools/validate_map01_formal.gd`，检查53个区域、全部原始顶点、配套底图尺寸与多档相机缩放的坐标一致性。图形模式还输出临时实机截图。

Debug编辑：Shift点击/拖动添加临时禁行，普通点击/拖动清除对应笔刷禁行；恢复不能覆盖外部JSON的红色阻挡。源多边形仍在外部工具中编辑。
