## 2. 共用像素、图层与视觉红线

### 2.1 世界像素基线

- 世界 Tile 源像素 `16×16`，逻辑显示 `48×48`；Pixel Art 使用 nearest。
- 地图 UI 仍以 `375×817` 视窗设计，Tile 规格不反推 UI 布局。
- 地形、阻挡、前景遮挡、交互高亮和碰撞语义分层交付，不把整张大地图烘焙成一张图片。
- 屋顶、树冠、拱门、前景山石、封链等遮挡层必须有可淡出区域和锚点说明。

### 2.2 最终图层顺序

```text
低细节地形底层
→ 道路/地形消耗/阻挡的平面大轮廓
→ 关键地标与可淡出前景
→ 世界对象棋子
→ 队伍、资源、敌群、Boss、入口等 UI Overlay 标记
→ 迷雾、选中、锁定与路径预览
```

- 队伍、资源点、敌群、Boss、副本入口、出生点和跨图出口不得烘焙进地形或地图视觉母版。
- 交互对象、状态变体和可淡出前景必须与基础地形分层。
- 迷雾使用运行时 Shader/Mask/Tile 状态，原则上不导出未知/已发现/可见三张完整地图。

### 2.3 导航底图优先

- 可玩区域约 `75%–85%` 使用低饱和、低对比、大面积连续平面。
- 普通可走底面只使用 `3–5` 个接近明度的基础色。
- 普通地面不允许每格随机散布碎石、草叶、裂纹、灵光、铜屑、尸骸、落叶或独立阴影。
- 细节预算只留给一、二级地标、进出口、Boss 区、封链/阵眼等导航结构。
- 不为每个 Tile 画黑色闭合外轮廓，正式地图不显示棋盘格或网格边界。
- 灰盒已确认的对象格中央至少保留约 `32×32` 逻辑像素标记静区，不放高光点、裂纹交点、小植物、尖锐黑影或近似标记颜色的点状装饰。
- 普通背景不得依赖更亮外发光、白色贴纸边或黑色厚底盘补救标记可读性。

### 2.4 纯俯视平面 2D 红线

- 摄像机固定为接近 `90°` 垂直向下的正交投影；无地平线、消失点、近大远小、透视收窄或斜向缩短。
- 所有可走区都是同一层完全平整的 2D 色块；不显示地面厚度、台阶立面、平台侧壁、崖壁侧面、深坑内壁或向下纵深。
- 高差与阻挡只用平面轮廓、边界、局部遮挡和大色块表达，不使用立体台地、悬浮岛或立体沟壑。
- 建筑、山门、阵眼、封链和机关只显示平面图形或正上方顶部剪影，不显示大面积正立面、侧面、厚度或内部纵深。
- 光影只允许极弱的平面明暗分区；禁止体积光、环境遮蔽、边缘光、法线高光、物体投影和用阴影塑造体积。
- 任意普通行走区都必须像平铺的 2D 地图，不像高处斜看的场景、沙盘或微缩模型。

### 2.5 Alpha 与禁止背景

- 地面 Tile 使用实际地表色铺满边缘；阻挡、地标、贴花、前景、图标和标记使用真实 RGBA Alpha。
- 绝对禁止 `#00FF00`、任何绿色键色、白底、黑底、棋盘格或投影展示板伪装透明。
- GPT 未返回真实 Alpha 时，只能作为人工清稿母版，不能直接导入游戏。

## 3. 地图素材统一生产工作流

本节是四张地图唯一的正式资产拆分入口。每张地图都必须先有上游规则和灰盒，之后才允许使用生成模型。
供应方优先级、ChatGPT 浏览器流程、Meowa 升级条件与积分门禁统一读取
[18 分册](18_地图生成式美术生产与模型分工规范.md)。`3.3`、`3.4` 的提示词只生成视觉母版；
`3.6` 的提示词只生成分组素材母版。任何生成输出都不能绕过 Tile Set 拆分、确定性清稿和 Godot 重拼。

### 3.1 阶段、输入、输出与回退

| 阶段 | 主要输入 | 生成模型 | 阶段输出 | 通过门槛 | 失败回退 |
|---|---|---|---|---|---|
| 1. 上游冻结 | 地图分册、PRD、数值中的地图尺寸/消耗/对象量 | 不参与 | 地图规范表、对象清单、状态清单 | 无来源冲突；未冻结项明确标记 | 回上游分册 |
| 2. Figma 灰盒 | 地图规范表、候选对象锚点、375×817 视窗 | 不参与 | 标注灰盒、碰撞图、GPT clean guide、标记测试 | 路线可达、地形消耗清楚、对象静区成立 | 改灰盒 |
| 3. 地图视觉母版 | 灰盒四类导出、视角参考、失败反例 | 参与 | 只含地形/大轮廓/关键地标的视觉母版 | 纯俯视、低噪点、不改路 | 改提示词或重做母版 |
| 4. Tile Set 需求表 | 灰盒与视觉母版 | 不参与 | terrain/连接/边缘/转角/阻挡/地标清单 | 灰盒每个格与状态都有资产去向 | 回灰盒或拆分表 |
| 5. 分组素材母版 | 已确认视觉母版、Tile Set 需求表、像素参考 | 参与 | 地面、道路、阻挡、前景、地标、贴花母版 | 同批比例/色盘/投影一致 | 单批重生，不重做整图 |
| 6. 人工像素清稿 | 分组母版 | 不参与 | 正式 `16×16` Tile、透明对象、状态变体 | 无缝、硬边、真实 Alpha、统一像素密度 | 回对应素材批次 |
| 7. Tiled/Godot 拼装 | 灰盒、正式 Tile、对象表 | 不参与 | 分层地图、碰撞、遮挡、对象与迷雾 | 结构与灰盒一致，不引用 GPT 整图 | 回 Tile 或拼装 |
| 8. 合成验收 | 375×817 探索页、七种标记、迷雾与路径 | 不参与 | 用户确认的地图试制视窗 | 俯视感、导航、标记和拼接全部通过 | 回底图/标记/图层 |

图片1、2。除图片5外，不上传其他游戏高精度地图、写实风景、绿色键色底或带水印图片。

### 3.5 从灰盒确认 Tile Set

Tile Set 不能从 GPT 母图目测裁切。先给灰盒每个格记录 `terrain_id`、地形消耗、阻挡/可走语义和
上下左右连接，再建立“灰盒使用拓扑 → 正式资产”的覆盖表。

道路四方向至少检查单点、水平/垂直直线、`4` 个端点、`4` 个转角、`4` 个 T 形和十字，共 `16` 种。
若最终 Tiled 自动地形采用八邻域 Blob/Wang Tile，只能在 Tiled 规则冻结后升级，不让 GPT 猜 `47` Tile。

Tile Set 需求表必须分开记录：

- 基础地面与低差异变体；
- 普通道路、危险地形及其连接拓扑；
- 上下左右边、外转角、内转角与斜向边；
- 大型阻挡的占格和碰撞底座；
- 可淡出前景及渐隐区域；
- 独立地标、交互锚点和状态变体；
- 低频装饰贴花；
- 运行时覆盖标记，后者不属于地形 Tile。

进入正式清稿前必须满足：

1. 灰盒每个格和每个对象状态都有明确资产去向。
2. 所有实际使用的道路与边缘拓扑都有对应 Tile。
3. 不依赖 GPT 整图像素补洞。
4. `10×10` 连续铺设无裂缝、明显重复焦点或棋盘噪点。
5. 普通/危险地形在灰度下可分，但不会抢过覆盖标记。
6. 地标、状态对象和可淡出前景均与基础地形分层。

### 3.7 确定性清稿与 Godot 拼装

可使用 Aseprite、Photoshop 或仓库内受审的确定性脚本进行清稿。脚本只允许执行裁切、Alpha 清理、
最近邻缩放、有限色盘、状态对齐、分层、联系表和 Tile 编译；不得自动创造主体设计、改变灰盒结构或
覆盖已 Approved 运行素材：

1. 统一像素颗粒、受限色盘和明暗方向。
2. 清除抗锯齿、柔边、半透明脏像素和错误背景。
3. 重建真正无缝的 `16×16` 地面、连接、边缘与转角。
4. 将阻挡视觉、碰撞底座、前景淡出区、地标锚点和状态分别导出。
5. 在 Tiled/Godot 按 Figma 灰盒重新拼图，不能导入 GPT 整张视觉母版覆盖结构。
6. 后置叠加对象、队伍、资源、敌群、Boss、入口、迷雾、路径和选中状态。
7. 新资源交给 Godot 编辑器自动导入并生成 `.import`，禁止手写或脚本伪造 `.import`。

### 3.8 地图共用验收 Gate

- 第一眼能确认摄像机接近 `90°` 垂直向下，无 2.5D、透视、平台厚度和侧面。
- 可走区是平整 2D 色块；道路、危险地形、阻挡和进出口无需文字即可理解。
- 不叠加标记时仍能靠大轮廓和一、二级地标定向；叠加标记后标记优先被读取。
- 七种标记在最浅、最深和噪点最高区域，以 `100%`、`75%`、`50%` UI 缩放及灰度图检查均可识别。
- 普通区域保持大面积安静色面；移除标记后不应每个小区域都有独立细节中心。
- Tile 无裂缝、错位或线性过滤；前景淡出后路径、对象和预警仍可读。
- 不出现 `#00FF00`、绿色键色、棋盘格、烘焙点位、文字、路径箭头、HUD、水印或 Logo。
- 用户人工确认风格、俯视感、标记可读性和 Tile 拼接后，地图才能进入 Approved。

### 6.8 本批生成顺序与验收

1. 先生成扎营、归营、队伍、背包四个操作图标，放入 Approved 操作按钮检查尺寸和风格。
2. 再生成弄点吃的、运功疗伤、继续探险三个扎营面板图标，并排放入图片5的实际按钮框检查操作语义与视觉重量。
3. 然后生成我方队伍、资源点、普通敌群和 Boss 四个高频地图标记，同时合成到 `map_01` 和
   `map_04`；普通敌群与 Boss 必须并排检查剪影层级。
4. 最后生成副本入口、出生点和跨图出口，三者放在同一地图截图中做灰度轮廓对照，但仍逐张生成。
5. 十四张图都通过单独查看与对应页面合成后，才可进入 Godot 导入；不得用绿色键色母图占位通过。

验收必须满足：

- 扎营图标不会被误认为回血药、食物或永久营地；归营图标不会被误认为归营符物品。
- 进食补给图标是“木钵与食气”操作，不是某一件食物物品，也不暗示恢复生命。
- 运功疗伤图标是“盘膝行气”，不是用药或复活；继续探险图标是“收卷休整物与前行足迹”，不是归营或跨图。
- 队伍操作图标明确是固定四人；地图队伍标记在一个 48×48 逻辑格内清楚且不遮挡相邻对象。
- 资源点与背包/宝箱不同；普通敌群的窄幅警戒幡与 Boss 的宽阔裂印在剪影、占比和灰度下都能立即区分。
- 副本入口是向内/向下的暗门，跨图出口是向外延伸的开放山门，出生点是扁平地面阵印。
- 所有标记在 `map_01`、`map_04` 和灰度截图中均可识别，不只依赖红、绿或发光颜色。
- 未知区不会提前显示对象；锁定、已处理和高亮状态没有烘焙进普通态 PNG。
- 十四张 PNG 均为真实 Alpha，图形外没有绿色、白色、黑色、棋盘格或抠图残边。

## 8. 敌人、精英与 Boss

  Sprite Sheet 特效表达。
