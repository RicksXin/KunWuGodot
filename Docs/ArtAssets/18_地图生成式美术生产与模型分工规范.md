# 《昆吾禁地》地图生成式美术生产与模型分工规范

版本：1.0
日期：2026-08-21
状态：项目级强制执行
适用范围：`map_01`–`map_04` 的灰盒、Tile、阻挡、前景、地标、Overlay Marker、地图操作图标、贴花、候选母图与 Godot 接入

## 1. 核心原则

地图美术统一采用“规格与结构先行、生成模型只产候选、确定性工具完成运行资产、用户执行视觉批准”的生产方式。

固定优先级：

```text
复用现有 Approved 素材
→ 本地确定性制作或处理
→ ChatGPT 会员网页生成
→ Meowa 受控升级
→ 用户视觉批准
```

- ChatGPT 是地图生成式美术的默认供应方；允许代理在用户已授权、已登录的浏览器中上传参考、提交提示词、下载原始结果。
- Meowa 是昂贵的异常升级通道，不是默认供应方。任何扣积分任务仍受
  [`../Tech/Meowa_API调用规范.md`](../Tech/Meowa_API调用规范.md) 和根 `AGENTS.md` 的逐次授权门禁约束。
- Codex/本地工具负责所有可以确定性完成的工作：事实审计、灰盒、规格、参考图、提示词、归档、Alpha 检查、裁切、像素化、缩放、分层、Tile 编译、联系表、Godot 组件、碰撞、场景组装和自动验证。
- 用户负责最终视觉 Gate。自动检查通过不等于 `Approved`。
- 不允许使用 GPT、Meowa 或任何生成器直接制作一张扁平的“最终运行地图”覆盖灰盒、Tile、碰撞、对象坐标或迷雾。

## 2. 固定分工矩阵

| 工作 | 默认执行者 | Meowa 是否允许 | 交付边界 |
|---|---|---|---|
| 策划/PRD、对象表和当前实现审计 | Codex | 否 | 只读事实审计 |
| 灰盒、路线、可走区、危险格、碰撞和对象静区 | Codex/Figma | 否 | 结构事实源，不是美术母图 |
| 参考裁切、需求板、提示词和资产契约 | Codex | 否 | 进入 `art/candidates/` |
| 地面、道路、困难地形连续风车母图 | ChatGPT | 失败升级时允许 | 只产连续母图，不产 15 张最终 Tile |
| Dual Grid `0x1–0xF` 编译和连接测试 | Codex | 否 | 确定性编译 |
| 山脊、阻挡和可淡出前景母图 | ChatGPT | 高难结构失败时允许 | 逐素材家族生成 |
| 普通单态/少量状态地标母图 | ChatGPT | 高难状态一致性失败时允许 | 逐地标家族生成 |
| 队伍、资源、敌群、Boss、副本、出生点、出口 Marker | ChatGPT | 默认否 | 每张独立透明 PNG |
| 探索和扎营操作图标 | ChatGPT | 默认否 | 每张独立透明 PNG |
| Alpha、裁切、硬边、调色、最近邻缩放、有限色盘 | Codex/人工像素清稿 | 否 | 不消耗生成积分 |
| 多状态对齐、锚点、碰撞和层拆分 | Codex | 否 | 状态语义不烘焙进错误图层 |
| Godot TileMap、组件、Overlay、迷雾和运行时状态 | Codex | 否 | Godot `4.7.1` 兼容 |
| `375×817`、灰度、`100% / 75% / 50%` 预览 | Codex | 否 | 候选验收证据 |
| 最终风格与实装确认 | 用户 | 否 | 明确批准后才能晋升 |

## 3. 供应方选择与升级规则

### 3.1 先判断是否需要生成

开始生成前必须依次检查：

1. 项目是否已经存在可复用的 Approved 素材或同家族组件。
2. 是否能通过本地裁切、重排、重着色、Alpha 清理、像素化或组合完成。
3. 是否只是规格板、碰撞图、联系表、Marker 安全区、Tile 编译或 Godot 预览；这些一律由 Codex 确定性完成。
4. 只有确实需要新的原创位图主体时，才进入 ChatGPT 或 Meowa。

### 3.2 ChatGPT 默认路径

- 一个提交只生成一个独立素材；同一地标的严格对齐状态家族可以作为一个明确任务。
- 不生成七宫格、Sprite Sheet、完整页面、带文字资产表或一张烘焙完整地图。
- 默认先生成一个候选。首个候选未检查前，不靠大量变体碰运气。
- 第一次失败后只允许一次针对性修正，例如只修正视角、轮廓、状态差异或 Alpha；修正时重申不变量。
- 浏览器若出现登录、验证码、会员额度确认或其他账户安全交互，由用户接手；代理不得规避。
- 必须下载原始 PNG；不得用网页截图、JPG、聊天缩略图或手工绿幕代替原始结果。

### 3.3 Meowa 升级条件

只有在下列至少一项成立时，才可以向用户提出 Meowa 方案：

- ChatGPT 初稿和一次针对性修正后仍无法保持接近 `90°` 的严格俯视。
- 多状态素材反复改变尺寸、锚点、基础轮廓或共享结构。
- 高价值大型地标持续违背参考图占格或结构，不是本地清稿能够修正的问题。
- 需要 Meowa 特有且已知价格、可计算输出上限、当前门禁允许的能力。

即使满足升级条件，也不得自动调用 Meowa。每一条扣分提交都必须重新展示用途、能力、输入、数量、输出契约、预计积分和最高积分，并取得用户对该次最高积分的明确批准。ChatGPT 失败不构成 Meowa 扣分授权。

### 3.4 禁止把 Meowa 用于

- 普通 Marker、普通操作图标或低频小贴花的批量碰运气。
- Alpha 清理、裁切、缩放、调色、像素化、联系表或合成预览。
- 分别生成 Dual Grid 的 15 张掩码 Tile。
- 直接生成最终运行地图、碰撞、坐标、迷雾或 Godot 场景。
- 自动重试失败 Job、自动增加变体或自动升级质量。

## 4. 按素材类别执行

### 4.1 地形、道路和困难地形

```text
灰盒拓扑
→ 材质参考与连续风车母图提示词
→ ChatGPT 母图（必要时受控升级 Meowa）
→ 本地规范化
→ 编译 `0x1–0xF`
→ 实心/走廊/L角/凹角/单格/洞/两种对角测试
→ TileMapDual 资源
```

模型只能生成连续母图或材质候选。15-piece、TileSet、连接掩码和 Godot 场景必须确定性编译。

### 4.2 阻挡和可淡出前景

按占格和功能拆成素材家族；生成模型只负责透明母图。Codex 负责裁切、碰撞底座、前景层、淡出规则、锚点和联系表。不得把不可走语义从图片反推到地图。

### 4.3 地标及状态

每次只处理一个地标家族，先冻结：

- 逻辑尺寸和交付尺寸；
- 底部中央或自定义锚点；
- 静态底座、状态覆盖层和可淡出前景；
- 永久碰撞、状态碰撞和开放通道；
- 允许变化与必须保持不变的区域。

生成母图验收后，由 Codex 提取分层运行 PNG、建立组件和计算状态轮廓一致性。对象奖励、事件文案和遭遇数据不得写入视觉组件。

### 4.4 Overlay Marker 和操作图标

- 默认全部使用 ChatGPT 会员网页生成，不使用 Meowa。
- 每张独立生成并保留真实 RGBA Alpha。
- Marker 必须同时放入 Map01 青灰底、深色测试板和灰度图，在 `100% / 75% / 50%` 下检查。
- 状态高亮、锁定、已处理、选中、次数和文字由 Godot 节点表达，不复制状态 PNG。

### 4.5 整体地图

视觉母版只锁定风格、色盘、细节密度和大轮廓，不是运行事实源。最终地图必须从灰盒、正式 Tile、独立阻挡、前景、地标组件、对象坐标、Overlay 和迷雾重新组装。

## 5. 每个素材家族的标准 Gate

### Gate 0：审计现有资产

- 搜索运行资源、母图、候选、组件、提示词、manifest 和历史验收。
- 明确哪些可以复用，哪些缺失，禁止重复生成已经批准的素材。

### Gate 1：冻结资产契约

至少记录：

```text
asset_id / filename / purpose / logical_size / delivery_size
alpha / anchor / states / layers / collision / references
prompt / avoid / output_candidate_dir / runtime_path / acceptance
```

未冻结坐标或内容统一标记 `UNVERIFIED`，不得借生成美术写入正式地图。

### Gate 2：准备生成输入

- 参考图分别声明为结构、风格、尺寸、色盘或编辑目标。
- 制作需求板、可复制提示词和失败反例。
- 提示词必须写清单张输出、真实 Alpha、视角、尺寸逻辑、不变量和禁止项。

### Gate 3：生成与原图归档

- 按第 3 节选择 ChatGPT 或经批准的 Meowa。
- 原始输出先进入对应 `art/source_archive/` 或 `art/candidates/`，不得直接覆盖 `assets/`。
- 保存来源、日期、最终提示词、参考图路径、模型/供应方、原始尺寸和 SHA-256。

### Gate 4：技术检查与清稿

- 检查原始格式、尺寸、真实 Alpha、边界、透明残色、裁切和多余主体。
- 用确定性工具完成裁切、硬 Alpha、最近邻缩放、有限色盘、状态对齐和分层。
- 自动处理只能生成候选，不能擅自改变主体设计或覆盖 Approved 运行素材。

### Gate 5：Godot 候选接入

- 新图交给 Godot 自动导入，不手写 `.import`。
- 使用共用组件、独立碰撞和运行时状态；不把业务规则写回 Sprite。
- 未经批准的坐标只进入独立 Demo 或候选预览，不进入正式 `map_01.tscn` 和产品数据。

### Gate 6：自动与人工验收

- 运行与风险匹配的图片、组件、场景和 Godot headless 验证。
- 输出联系表、正常比例截图、灰度图和必要的状态对照。
- 用户明确确认视觉后，才可从候选晋升到 `assets/` 并回填 TODO/manifest。

## 6. 目录与晋升规则

| 阶段 | 目录 | 规则 |
|---|---|---|
| 原始生成结果 | 对应 `art/source_archive/`；Meowa 固定为 `art/source_archive/meowa/` | 保留原图、来源和 SHA，不进入运行时 |
| 参考、需求板和待审候选 | `art/candidates/<asset-family>/` | 可重复生成，不视为正式素材 |
| 清稿后的候选运行图 | `art/candidates/<asset-family>/compiled/` | 必须经过预览和验证 |
| Approved 运行素材 | `assets/` | 用户视觉批准后才能晋升 |
| Godot 组件 | `scenes/maps/components/` | 视觉和状态职责分离 |
| 验证脚本 | `tools/validate_*.gd` 或确定性本地工具 | 测试传入 `-- --no-profile-write` |

不得用新生成结果直接覆盖已有 Approved 文件；除非用户明确要求替换，否则使用版本化候选文件名。

Git 边界：整个 `art/` 是本地制作工作区，除目录说明外不提交到主仓库；主仓库只提交晋升到
`assets/` 的 Approved 运行素材、程序、配置和必要文档。运行场景与业务脚本不得依赖 `res://art/`。
需要备份或多人协作的源文件与候选应进入独立私有美术仓库或受控存储。

## 7. 当前 Map01 默认执行顺序

1. 保留现有已验收地面、道路、困难地形、阻挡、阵灯、万修之门、残碑、废营、暗道和阶梯，不重复生成。
2. 七个 Overlay Marker 通过 ChatGPT 浏览器逐张生成；Meowa 暂不参与。
3. Codex 完成 Alpha、清稿、`96×96 / 72×72 @3x`、灰度与缩放预览，并建立共用 Marker 组件。
4. 七个探索/扎营操作图标继续使用 ChatGPT 浏览器逐张生成。
5. Codex 完成路径点、终点、阻挡、中断和低频贴花中可以确定性制作的部分；真正需要原创主体时再走 ChatGPT。
6. 最终地图由 Codex 在 Godot 中按灰盒和组件组装，不重新生成整张高清地图。
7. 正式对象坐标冻结前，所有新增地标和 Marker 只进入候选预览或独立 Demo。

## 8. 每次任务开始与交付检查

任何涉及地图图片生成、提示词、母图检查、清稿、Marker、图标、Tile、阻挡、前景或地标的任务，开始前必须回答：

1. 是否已有可复用素材？
2. 这一步是生成式工作还是确定性工作？
3. 如果生成，为什么 ChatGPT 足够或为什么需要提出 Meowa？
4. 输出进入候选目录还是已获得用户批准可以晋升？
5. 是否会改变正式坐标、碰撞、产品数据或运行场景？
6. 本轮需要哪些自动验证和用户视觉确认？

交付时必须报告：供应方、最终提示词/规格位置、原始与运行文件、验证结果、是否使用 Meowa 及实际积分、正式场景是否修改、仍待用户确认的视觉事项。
